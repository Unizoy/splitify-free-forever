# Money rules (checklist)

Spec: `planning/05-money-engine.md`. Contract: `planning/reference/money_vectors.json` (generated by
`planning/reference/money_reference.py` — regenerate, never hand-edit; copy to `test/fixtures/`).

1. Amounts are `int` minor units + currency code (`Money`). Never `double`, `num`, `toStringAsFixed` maths or
   `num.parse` on amounts. Parse user input with `AmountExpression` (Decimal) → minor units.
2. Every split/allocation goes through `lib/core/money` (`split`, `allocateEqual`, `allocateRatio`). Never divide
   amounts inline in widgets, repositories or SQL outside the `money` schema.
3. Members are always passed in **fixed order** (`position`, then `id`). Don't sort by name before allocating.
4. Balances are per currency. Never add amounts of different currencies; converted views use the saved fx fields
   on each record only.
5. Conversions: `convert()` with explicit half-away-from-zero rounding; convert totals then re-allocate parts.
   Saved rates are never recomputed.
6. Display only through `MoneyFormatter` (en_IN grouping, ₹ symbol, hide `.00` in lists).
7. Server and client must agree: if you change an algorithm, change the oracle, regenerate vectors, update Dart and
   SQL in the same phase, and run both test suites.
8. Tests: add a vector or property test for every new money behaviour. Coverage of `lib/core/money` stays 100 %.
9. `tool/guards.dart` fails on `double`/`num` in money paths — fix the code, never the guard.
