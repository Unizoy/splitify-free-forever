# Emulator end-to-end testing

Device: AVD `Pixel_9_API_36` → serial `emulator-5554`. Start/repair it with the `dev-env` skill.
`$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"`. App id `com.unizoy.splitify`.
Artefacts (screenshots, logs) go to `C:\Users\mohit\OneDrive\Desktop\theCode\splitify-artifacts\phase-NN\`
(outside the repo; create the folder if missing).

## 1. Build, install, launch

```powershell
flutter build apk --debug --dart-define-from-file=secrets/env.dev.json
& $adb install -r build\app\outputs\flutter-apk\app-debug.apk
& $adb shell am start -n com.unizoy.splitify/.MainActivity
```
Fresh state when a test needs it: `& $adb shell pm clear com.unizoy.splitify` (only the app's data — never wipe
the emulator).

## 2. Signing in automatically

Debug builds have a dev-only email+password login (D-007). Test users: `e2e-a@splitify.test`, `e2e-b@splitify.test`,
`e2e-c@splitify.test`, password from `secrets/env.dev.json` key `E2E_PASSWORD` (generated by phase 05; the dev
project has "Confirm email" off, so the harness creates them with `signUp` when missing). Integration tests call the
dev login directly; manual adb flows use the deep link `splitify://dev/login?user=e2e-a` (debug only, phase 05).
Google sign-in end-to-end is tested only when `owner-inputs.json` says `emulator_has_google_account: true`.

## 3. Running suites

```powershell
flutter test integration_test --dart-define-from-file=secrets/env.dev.json -d emulator-5554
# Patrol (native dialogs, notifications, permission prompts), once phase 01 adds it:
dart run patrol_cli:main test -t integration_test/patrol --dart-define-from-file=secrets/env.dev.json
```
Second-user actions (another member adding an expense) are performed by the test harness through the Supabase
API as user B (see `planning/09-testing-strategy.md`, "multi-user harness"), not by a second emulator.

## 4. Scripted adb interactions

```powershell
& $adb shell input tap X Y                        # coordinates from a uiautomator dump
& $adb shell input text "Dinner"                  # spaces: use %s
& $adb shell input keyevent KEYCODE_BACK
& $adb shell uiautomator dump /sdcard/ui.xml; & $adb pull /sdcard/ui.xml $env:TEMP\ui.xml
& $adb shell am start -a android.intent.action.VIEW -d "splitify://group/<id>" com.unizoy.splitify
& $adb shell pm grant com.unizoy.splitify android.permission.POST_NOTIFICATIONS
& $adb shell pm grant com.unizoy.splitify android.permission.CAMERA
```
Prefer semantic finders in integration tests over coordinates; use adb only for things tests can't reach.

## 5. Offline / airplane mode

```powershell
& $adb shell cmd connectivity airplane-mode enable     # offline
& $adb shell cmd connectivity airplane-mode disable    # back online
& $adb shell svc wifi disable; & $adb shell svc data disable   # alternative
```
Always re-enable networking at the end of a test (use try/finally in scripts). Kill the app mid-sync with
`& $adb shell am force-stop com.unizoy.splitify` to test queue durability.

## 6. Screenshots and logs

```powershell
$dir = "C:\Users\mohit\OneDrive\Desktop\theCode\splitify-artifacts\phase-NN"; New-Item -ItemType Directory -Force $dir | Out-Null
& $adb exec-out screencap -p > "$dir\groups-light.png"     # in PowerShell use: cmd /c "adb exec-out screencap -p > file"
& $adb shell "cmd uimode night yes"   # dark mode on;  "night no" = light
& $adb shell settings put system font_scale 2.0          # large text; reset with 1.0
& $adb logcat -d -s flutter:V > "$dir\logcat.txt"
```
PowerShell's `>` corrupts binary output; capture screenshots with
`cmd /c "`"$adb`" exec-out screencap -p > `"$dir\name.png`""` or `& $adb shell screencap -p /sdcard/s.png; & $adb pull /sdcard/s.png "$dir\name.png"`.
Then view the PNG with the Read tool (that is how you "see" the screen).

## 7. Notifications (phase 13+)

```powershell
& $adb shell dumpsys notification --noredact | Select-String -Pattern "com.unizoy.splitify" -Context 0,12
```

## 8. Biometrics for app lock (phase 18)

Enroll a fingerprint once: Settings → Security → set a PIN, add fingerprint, and when asked to touch the sensor run
`& $adb -e emu finger touch 1`. In tests, trigger the prompt then send `& $adb -e emu finger touch 1` (match) or
`... touch 2` (no match).

## 9. Fake UPI handler (phase 11+)

`tool/fake_upi_app/` (built in phase 11) is a tiny debug app registered for `upi://pay`. Install it with
`& $adb install -r tool\fake_upi_app\build\app\outputs\flutter-apk\app-debug.apk`. It writes the last received URI
to its logcat tag `FAKE_UPI` — assert on `pa`, `pn`, `am`, `cu=INR`, `tn`. Uninstall it to test the
"no UPI app installed" path: `& $adb uninstall dev.splitify.fakeupi`.
