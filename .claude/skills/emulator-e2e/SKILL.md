# Emulator end-to-end testing

Device: AVD `Pixel_9_API_36` → serial `emulator-5554`. Start/repair it with the `dev-env` skill.
`$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"`. App id `com.unizoy.splitify`.
Artefacts (screenshots, logs) go to `C:\Users\mohit\OneDrive\Desktop\theCode\splitify-artifacts\phase-NN\`
(outside the repo; create the folder if missing).

## 1. Build, install, launch

```powershell
flutter build apk --debug --dart-define-from-file=secrets/env.dev.json
& $adb install -r build\app\outputs\flutter-apk\app-standard-debug.apk
& $adb shell am start -n com.unizoy.splitify/.MainActivity
```
Flavours (D-028): no `--flavor` = `standard` (no payment bubble); payment-bubble checks need `--flavor full`
(APK `app-full-<mode>.apk`, `integration_test/capture_bubble_test.dart` via `tool/e2e/capture_e2e.ps1`). Both use
the same app id, so installing one replaces the other.
Fresh state when a test needs it: `& $adb shell pm clear com.unizoy.splitify` (only the app's data — never wipe
the emulator).

## 2. Signing in automatically

Debug builds have a dev-only email+password login (D-007). Test users: `e2e-a@splitify.test`, `e2e-b@splitify.test`,
`e2e-c@splitify.test`, password from `secrets/env.dev.json` key `E2E_PASSWORD` (generated by phase 05; the dev
project has "Confirm email" off, so the harness creates them with `signUp` when missing). Integration tests call the
dev login directly; manual adb flows use the deep link `splitify://dev/login?user=e2e-a` (debug only, phase 05).
Google sign-in end-to-end is tested only when `owner-inputs.json` says `emulator_has_google_account: true`.

## 3. Running suites

```powershell
flutter test integration_test --dart-define-from-file=secrets/env.dev.json -d emulator-5554
# Patrol (native dialogs, notifications, permission prompts), once phase 01 adds it:
dart run patrol_cli:main test -t integration_test/patrol --dart-define-from-file=secrets/env.dev.json
```
Second-user actions (another member adding an expense) are performed by the test harness through the Supabase
API as user B (see `planning/09-testing-strategy.md`, "multi-user harness"), not by a second emulator:
`integration_test/support/harness.dart` (`devEnv()`, `pumpUntil`, `HarnessUser.signIn(env, 'e2e-b')`).

**DNS on this PC (S-214):** the ISP answers plain DNS for `*.supabase.co` with a block page, so the emulator cannot
reach the dev project by name (`AuthFailure(offline)`, nothing in the edge logs). Always add the PC's answer:
```powershell
$e = Get-Content secrets\env.dev.json -Raw | ConvertFrom-Json
$ip = (Resolve-DnsName ([Uri]$e.SUPABASE_URL).Host -Type A | ? IPAddress | Select -First 1).IPAddress
flutter test integration_test/<file>.dart -d emulator-5554 --dart-define-from-file=secrets/env.dev.json "--dart-define=PIN_HOST_IP=$ip"
```
Tests must call `devEnv()` before creating any Supabase client (it installs the pin).

## 4. Scripted adb interactions

```powershell
& $adb shell input tap X Y                        # coordinates from a uiautomator dump
& $adb shell input text "Dinner"                  # spaces: use %s
& $adb shell input keyevent KEYCODE_BACK
& $adb shell uiautomator dump /sdcard/ui.xml; & $adb pull /sdcard/ui.xml $env:TEMP\ui.xml
& $adb shell am start -a android.intent.action.VIEW -d "splitify://group/<id>" com.unizoy.splitify
& $adb shell pm grant com.unizoy.splitify android.permission.POST_NOTIFICATIONS
& $adb shell pm grant com.unizoy.splitify android.permission.CAMERA
```
Prefer semantic finders in integration tests over coordinates; use adb only for things tests can't reach.

## 5. Offline / airplane mode

```powershell
& $adb shell cmd connectivity airplane-mode enable     # offline
& $adb shell cmd connectivity airplane-mode disable    # back online
& $adb shell svc wifi disable; & $adb shell svc data disable   # alternative
```
Always re-enable networking at the end of a test (use try/finally in scripts). Kill the app mid-sync with
`& $adb shell am force-stop com.unizoy.splitify` to test queue durability.

## 6. Screenshots and logs

```powershell
$dir = "C:\Users\mohit\OneDrive\Desktop\theCode\splitify-artifacts\phase-NN"; New-Item -ItemType Directory -Force $dir | Out-Null
& $adb exec-out screencap -p > "$dir\groups-light.png"     # in PowerShell use: cmd /c "adb exec-out screencap -p > file"
& $adb shell "cmd uimode night yes"   # dark mode on;  "night no" = light
& $adb shell settings put system font_scale 2.0          # large text; reset with 1.0
& $adb logcat -d -s flutter:V > "$dir\logcat.txt"
```
PowerShell's `>` corrupts binary output; capture screenshots with
`cmd /c "`"$adb`" exec-out screencap -p > `"$dir\name.png`""` or `& $adb shell screencap -p /sdcard/s.png; & $adb pull /sdcard/s.png "$dir\name.png"`.
Then view the PNG with the Read tool (that is how you "see" the screen).

## 7. Notifications (phase 13+)

```powershell
& $adb shell dumpsys notification --noredact | Select-String -Pattern "com.unizoy.splitify" -Context 0,12
```

## 8. Biometrics for app lock (phase 18)

Enroll a fingerprint once: Settings → Security → set a PIN, add fingerprint, and when asked to touch the sensor run
`& $adb -e emu finger touch 1`. In tests, trigger the prompt then send `& $adb -e emu finger touch 1` (match) or
`... touch 2` (no match).
Without a fingerprint (faster, used by phase 18): `powershell -File tool\e2e\run_lock_e2e.ps1` sets PIN 1234, runs
`integration_test/app_lock_test.dart` (`LOCK_E2E=true`), types the PIN on each `LOCK-PROMPT`, checks `FLAG_SECURE`
in `dumpsys window windows`, sends the app home and back, and clears the PIN in `finally`. Screenshots of a
`FLAG_SECURE` window come out black — that is expected.

## 8b. Real Google sign-in, email codes and push (D-026, S-235)

The real app with the DNS pin, as a release x64 APK (signed with the debug key → the registered debug SHA-1 works):
```powershell
flutter build apk --release --target-platform android-x64 -t integration_test/support/pinned_main.dart `
  --dart-define-from-file=secrets/env.dev.json "--dart-define=PIN_HOST_IP=$ip"
```
Install, `pm clear` + `pm revoke … POST_NOTIFICATIONS` for a first-run check, drive with uiautomator taps. Google:
"Continue with Google" → "Choose an account" → (first time) "Agree and share". Push: the second person acts from the
PC through the normal API (supabase-js as e2e-b: `join_group`, `apply_mutations`, `send_reminder`); check
`net._http_response` for `{"outcome":"sent","delivered":1}`; "killed" = HOME + `am kill` (never `force-stop`: a
stopped app gets no FCM). Never open another app's inbox; grey out the account email in kept screenshots.

## 9. Fake UPI handler (phase 11+)

`tool/fake_upi_app/` (phase 11, S-126) is a tiny Java debug app (package `dev.splitify.fakeupi`) registered for
`upi://pay`: it logs the link with logcat tag `FAKE_UPI`, shows it 1.5 s and returns. Build/install/remove:
`.\tool\fake_upi_app\build.ps1 [-Install | -Uninstall]` (uses `android\gradlew.bat` when Flutter generated it, else the
Gradle 9.5 distribution in `%USERPROFILE%\.gradle`; APK `tool\fake_upi_app\app\build\outputs\apk\debug\app-debug.apk`).
Full check (hold the lock, ~5 min): `powershell -File tool\fake_upi_app\run_upi_e2e.ps1` → installs it, runs
`integration_test/friends_upi_test.dart`, compares the test's `UPI-EXPECT <uri>` print with the `FAKE_UPI` logcat line
(TC-26-02; an app cannot read another app's logcat, so the host compares), then uninstalls it and runs the
"No UPI app found" path (`--dart-define=FAKE_UPI=absent`, TC-26-03).

## 10. Full regression and background sync (phase 19)

- All plain device tests under one lock hold: `powershell -File tool\e2e\run_suite.ps1 -Files groups_test,sync_offline_test,...`
  (stops starting new files after `-MaxMinutes 28`; logs `splitify-artifacts\phase-NN\it-<name>.log`, one `RESULT` line
  per file). Special runners: `tool\e2e\airplane.ps1`, `tool\e2e\perf.ps1`, `tool\e2e\run_lock_e2e.ps1`,
  `tool\fake_upi_app\run_upi_e2e.ps1`, `tool\e2e\capture_e2e.ps1`, `tool\e2e\background_sync.ps1`. When a wrapper starts
  the scripts that don't load `tool\env.ps1` themselves, run them as `powershell -Command ". tool\env.ps1; & <script>"`.
- Real WorkManager run (S-160): `powershell -File tool\e2e\background_sync.ps1` → queues a change offline, sends the app
  home, network back on, forces the app's jobs; pass = outbox empty + server row + logcat
  `Worker result SUCCESS … BackgroundWorker` (`background-sync-logcat.txt`).
